# 自建东京 VPS：线路与 IP 初步评估

时间：2026-10-18 09:17–09:26（UTC+8）。由独立探索子代理完成；主代理核对报告与证据口径。单地点短时样本，不代表晚高峰或长期 SLA。

## 核心结论

- **IPv6 Reality**：本轮稳定完成样本，短下载约 **40 Mbps**，可作为偏保守的默认候选。
- **IPv6 Hy2**：本轮通过，约 **51–80 Mbps**；热 QUIC 会话有优势，但现配置关闭证书校验，应另行处理身份校验。
- **IPv4 Reality**：TCP 443 可达，代理请求多数失败、隔离 vender 对照偶有成功，应定性为当前不稳定，而非完全被阻断。
- **IPv4 Hy2**：本轮未取得完整 HTTPS 成功，尚不能视为可靠回退。
- IP 为日本东京 **AS3258 / xTom Japan** 机房属性；没有充分证据授予“住宅”“原生干净”或特定业务风控通过标签。

没有切换用户当前节点、修改代理配置/路由或远端服务，也没有安装测速软件。

## 方法与入口证据

只评估 VPS IPv4 `195.245.241.92` 与 IPv6 `2a12:a301:2014::61` 的四个入口，不评估机场。
本机 TUN 常驻，因此所有入口探测及独立 sing-box 出站显式绑定物理出口；检查主路由、策略路由、`route get … oif` 和实际 socket，避免把机场套娃测速算作 VPS 线路。
隔离 sing-box 1.14.3 仅监听回环，关闭 TUN；入口使用字面 IP，目标 DNS 经被测 VPS 的 Cloudflare DoH，不依赖本机 FakeIP。

绑定出口直访 Cloudflare 的本机 IPv4/IPv6 HTTPS 均超时，只说明这两个直连目的失败，不把它当作 VPS 失败。
IPv4 SSH 只读检查成功；IPv6 SSH 因缺可信主机密钥记录拒绝，未跳过验证，不能据此归因 IPv6 不通。

| 入口裸测 | IPv4 | IPv6 |
|---|---|---|
| ICMP 5 次 | 5/5；最小/均值/最大 121/190/292 ms | 5/5；116/133/168 ms |
| TCP 443，5 次 | 122.8、125.0、125.2、122.7、122.4 ms | 116.5、122.0、116.9、120.6、121.2 ms |

零丢包小样本不是稳定性保证；ICMP 和 TCP 成功也不保证 Reality/Hy2 数据面成功。

## 代理数据面与短下载

trace 为完整 HTTPS 请求耗时，不是裸 RTT。每入口测试三个 IPv4 目的 trace、一个 IPv6 目的 trace，再对同一 CDN 对象下载两次。

| 节点 | 入口族 | IPv4 目的 trace | IPv6 目的 trace | 两次 8 MiB 下载 | 实际出口 |
|---|---|---|---|---|---|
| JP-1 / Reality | v4 | 三次均约 8 秒超时 | 超时 | 均 0 字节 | 首轮未确认 |
| JP-1-V6 / Reality | v6 | 0.648/0.625/0.627 秒，3/3 | 0.554 秒成功 | 1.660/1.693 秒；40.42/39.64 Mbps | v4/v6 均匹配 VPS |
| JP-1-Hy2 | v4 | 三次均失败 | SOCKS 失败 | 均 0 字节 | 未确认 |
| JP-1-Hy2-V6 | v6 | 0.596/0.259/0.262 秒，3/3 | 0.259 秒成功 | 1.322/0.834 秒；50.77/80.48 Mbps | v4/v6 均匹配 VPS |

成功下载均为 HTTP 200、精确 8,388,608 字节。Mbps 按字节数/总耗时×8/10⁶计算，包含建连开销，不是套餐带宽认证。
Hy2 后两次 trace 复用已有 QUIC 会话，不能把热连接优势解释为物理线路更短。

为排除手写测试配置差异，追加隔离 vender 对照，同样不改变生产 daemon：IPv4 Reality 的 HTTP TLS EOF，但 SOCKS 有一次成功并确认 VPS 日本出口；IPv4 Hy2 仍未成功；IPv6 Reality 两种代理入口均成功。
随后两个 IPv4 入口复测仍失败。因此只能说 IPv4 当前不宜依赖，不能唯一归因运营商过滤、协议渲染或服务器策略。
此前 `DEBUG-RESULTS.md` 中四入口均成功是另一时段的历史记录，本报告保留而非覆盖该事实。

两个可用 IPv6 入口访问 Google generate_204 得到 HTTP 204；OpenAI `/v1/models` 返回明确缺少 bearer 认证的 401，说明网络/TLS/HTTP 可达，但**不证明账号可用、区域准入或风控豁免**。

## VPS 自身与 IP 质量

只读 SSH 确认 xray、hysteria-server 为 active，TCP 443、UDP 8443 在监听；2 vCPU、约 1.9 GiB 内存、负载约 0.09。
VPS 自身分别经 v4/v6 下载相同 8 MiB 对象，约 409/506 Mbps。它只是极短的出口突发样本；与本机代理下载的差距可提示入口路径等因素，不能据此定位瓶颈或建议升级套餐。

公开线索通过 Tavily 查询：

- IPinfo 双栈页指向东京、日本、AS3258 xTom Japan、Hosting；IPv4 公司为 Owl Limited。
- bgp.tools IPv4 前缀页与 HE IPv6 页支持 AS3258 归属，IPv6 有 IRR/RPKI Valid 线索。注册主体、运营商、零售品牌并不等同。
- bgp.tools 同时出现缓存性的“not visible in DFZ”和起源/上游信息，与当前可达性矛盾，不采信为实时撤路证据。
- Scamalytics 标记 Server=Yes，列举的 Firehol/IP2ProxyLite/IPsum/Spamhaus/X4Bnet 为 No；这不是逐库实时独立查询，置信度有限。
- IPinfo 的标题与正文隐私字段不完全一致；AbuseIPDB 提取失败。因此不采用单一风险分数，不推断历史无举报。

ASN/机房属性置信度较高；“列举黑名单未见命中”线索置信度中低；特定业务风控仍未知。

## 建议与限制

1. 偏交互稳定性：优先考虑 IPv6 Reality；偏吞吐：保留 IPv6 Hy2，但评估证书校验与 UDP 兼容性。
2. IPv4 专项复测应先分离时段、目的域名/字面 IP、出口地址族、协议握手，不先盲目修改服务器配置或购买更大带宽。
3. 本地 IPv6 不可用时仍需可靠 IPv4 回退；同一 VPS 四个入口并非跨服务器容灾。是否增设异地异运营商备机由用户决定。

有效下载共 48 MiB（代理侧 32 MiB、VPS 自身 16 MiB）；按代理链路两段及失败尝试的预设上限保守计，下载预算约 176 MiB，另有未逐包统计的协议开销。单对象最大 8 MiB、请求有限时、无无限测速。
全部测试进程已退出，私有配置和原始脚本仅留本机受限目录，不上传凭据。未验证晚高峰、长期丢包、跨运营商路径、满速 CPU、业务账号准入；上述建议不自动变更用户默认选择。
